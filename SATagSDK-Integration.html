SATagSDK 接入说明

统一接入 AppsFlyer、Facebook、TikTok 和 Firebase Analytics 打点。SDK 内部使用 Objective-C 实现，Objective-C、Swift 与 Expo iOS 工程均可直接调用。

重要：AppsFlyer 是必接渠道 初始化接口必须同时传入 AppsFlyer devKey 和 appleAppID。任一参数为空时，SATagSDK 不会初始化其它渠道。
最低系统iOS 13.0
当前版本1.1.0
实现语言Objective-C，支持 Swift 直接调用

1. CocoaPods 集成

集成全部渠道

在 Podfile 中添加以下内容。默认包含 Core、AppsFlyer、Facebook、TikTok 和 Firebase。

target 'YourApp' do
  pod 'SATagSDK', '~> 1.1'
end

执行 pod install，之后使用生成的 .xcworkspace 打开工程。

按需选择渠道

AppsFlyer subspec 必须保留，Facebook、TikTok 和 Firebase 可以按业务需要选择。

# AppsFlyer + Facebook
pod 'SATagSDK', :subspecs => ['AppsFlyer', 'Facebook']

# 仅 AppsFlyer
pod 'SATagSDK', :subspecs => ['AppsFlyer']

# AppsFlyer + TikTok
pod 'SATagSDK', :subspecs => ['AppsFlyer', 'TikTok']

# AppsFlyer + Firebase
pod 'SATagSDK', :subspecs => ['AppsFlyer', 'Firebase']

2. XCFramework 集成

不使用 CocoaPods 时，直接使用 SDK 发布方提供的单包发布物。接入方不需要获取 SATagSDK 源码工程，也不需要执行 SDK 构建脚本。

请向 SDK 发布方获取对应版本的 ZIP，例如：

SATagSDK-1.1.0.zip

解压后，ZIP 根目录包含以下文件：

文件用途谁需要使用
SATagSDK.xcframework 实际接入宿主 App 的 SDK 二进制包，拖入 Xcode 工程使用。 开发人员
SATagSDK-Integration.html 当前这份可视化接入说明，可直接用浏览器打开，查看集成步骤、配置和代码示例。 开发人员
SATagSDK-Integration.md 结构化接入规范，供大模型、代码助手或自动化接入工具读取和执行。开发人员通常不需要直接阅读。 大模型、代码助手
  1. 解压 ZIP。
  2. 将 SATagSDK.xcframework 拖入宿主工程。
  3. 在 Target 的 Frameworks, Libraries, and Embedded Content 中确认已添加。
  4. 按 Xcode 对动态依赖的提示完成 Embed 配置。

XCFramework 已包含 AppsFlyer、Facebook、TikTok 和 Firebase 二进制依赖，不要在同一宿主工程中重复添加这些渠道的 CocoaPods 依赖。

3. Expo iOS 集成

Expo 接入需要独立安装 satag-sdk-expo 原生桥接包。桥接层使用 Objective-C React Native Native Module，底层仍调用同一份 SATagSDK 二进制。

支持 Expo Prebuild、Expo development build 和 EAS iOS Build；不支持 Expo Go，因为 Expo Go 不包含本项目的自定义原生模块。当前仅支持 iOS。

请使用 SDK 发布方提供的 npm 包或私有 registry 包。接入方不需要获取 SATagSDK 源码工程，也不需要执行 SATagSDK 的构建脚本；如果公开 npm 尚未提供该包，请向发布方索取 npm tarball 或内部包地址。

npm install satag-sdk-expo

如果使用 Firebase，将 Firebase 控制台下载的 GoogleService-Info.plist 放入 Expo 工程，并在 app.json 或 app.config.js 中配置：

{
  "expo": {
    "plugins": [
      [
        "satag-sdk-expo",
        {
          "googleServicesFile": "./GoogleService-Info.plist"
        }
      ]
    ],
    "ios": {
      "googleServicesFile": "./GoogleService-Info.plist"
    }
  }
}

添加或修改原生依赖后重新执行 npx expo prebuild，并使用 development build 或 EAS Build。不能只重新加载 Metro。

import * as SATagSDK from "satag-sdk-expo";

const initializationResults = await SATagSDK.initialize({
  appsFlyerDevKey: "YOUR_APPSFLYER_DEV_KEY",
  appleAppID: "YOUR_APPLE_APP_ID"
});

const results = await SATagSDK.track("purchase", {
  product_id: "sku_001",
  price: 6,
  currency: "CNY"
});

await SATagSDK.trackFirebase("screen_view", {
  screen_name: "Home"
});

await SATagSDK.presentDebugView();

4. Info.plist 配置

Facebook

<key>FacebookAppID</key>
<string>YOUR_FACEBOOK_APP_ID</string>
<key>FacebookClientToken</key>
<string>YOUR_FACEBOOK_CLIENT_TOKEN</string>
<key>FacebookDisplayName</key>
<string>Your App Name</string>
键名要求
FacebookAppID初始化必需
FacebookClientToken建议配置
FacebookDisplayName建议配置

TikTok

<key>TikTokAccessToken</key>
<string>YOUR_TIKTOK_ACCESS_TOKEN</string>
<key>TikTokAppID</key>
<string>YOUR_TIKTOK_APP_ID</string>
<key>TikTokTTAppID</key>
<string>YOUR_TIKTOK_TT_APP_ID</string>

TikTok 三项配置均为初始化必需。兼容别名：TikTokBusinessAccessToken、TikTokBusinessAppID、TikTokBusinessTTAppID。

Firebase

从 Firebase 控制台下载 GoogleService-Info.plist，加入宿主 App 的主 Target。文件至少需要包含 GOOGLE_APP_ID；如果使用 Expo，请按上面的 Expo 配置提供同一文件。

AppsFlyer 参数不由 SATagSDK 从 Info.plist 读取，必须通过初始化接口传入。

5. 初始化

建议在 App 启动阶段调用。SATagSDK 会自动 Hook App 生命周期，并保留宿主 AppDelegate 的原始实现。

Objective-C

#import <SATagSDK/SATagSDK.h>

[[SATagSDK sharedInstance]
    initializeWithAppsFlyerDevKey:@"YOUR_APPSFLYER_DEV_KEY"
                        appleAppID:@"YOUR_APPLE_APP_ID"
                        completion:^(NSArray<SATagInitializationResult *> *results) {
    for (SATagInitializationResult *result in results) {
        NSLog(@"%@ state=%ld reason=%@",
              result.providerName,
              (long)result.state,
              result.reason);
    }
}];

Swift

import SATagSDK

SATagSDK.sharedInstance().initialize(
    withAppsFlyerDevKey: "YOUR_APPSFLYER_DEV_KEY",
    appleAppID: "YOUR_APPLE_APP_ID"
) { results in
    results.forEach { result in
        print("\(result.providerName): \(result.state) - \(result.reason)")
    }
}

6. 事件打点

统一广播

[[SATagSDK sharedInstance]
    trackEvent:@"purchase"
        parameters:@{
            @"product_id": @"sku_001",
            @"price": @6.0,
            @"currency": @"CNY"
        }
        completion:^(NSArray<SATagEventResult *> *results) {
    for (SATagEventResult *result in results) {
        NSLog(@"%@ state=%ld reason=%@",
              result.providerName,
              (long)result.state,
              result.reason);
    }
}];
SATagSDK.sharedInstance().track(
    event: "purchase",
    parameters: [
        "product_id": "sku_001",
        "price": 6.0,
        "currency": "CNY"
    ]
) { results in
    results.forEach { result in
        print("\(result.providerName): \(result.state)")
    }
}

单渠道事件

Objective-CSwift
trackAppsFlyerEvent:parameters:completion:trackAppsFlyer(event:parameters:completion:)
trackFacebookEvent:parameters:completion:trackFacebook(event:parameters:completion:)
trackTikTokEvent:parameters:completion:trackTikTok(event:parameters:completion:)
trackFirebaseEvent:parameters:completion:trackFirebase(event:parameters:completion:)

参数类型为 Objective-C 的 NSDictionary<NSString *, id> *，Swift 对应 [String: Any]。事件名不能为空。

7. DebugView

// Objective-C
[[SATagSDK sharedInstance] presentDebugViewFromViewController:self];

// Swift
SATagSDK.sharedInstance().presentDebugView(from: self)

DebugView 展示已检测到的渠道、配置来源、初始化状态、失败原因和脱敏后的配置值，不展示完整 Key、Token 或 App ID。

8. 状态说明

初始化状态含义
Initialized本地初始化调用完成，可以打点
MissingConfiguration缺少必要配置，修复后重新初始化
NotIntegrated工程未集成对应渠道依赖
Failed初始化失败或被必接渠道规则跳过
AlreadyInitialized已初始化，可以继续打点
事件状态含义
Accepted已调用第三方事件入口
NotInitialized先完成 SATagSDK 初始化
NotIntegrated添加对应渠道依赖
Failed读取 reason 并继续业务流程
InvalidEvent使用非空事件名

9. 接入验收清单

  • iOS Deployment Target 为 13.0 或更高。
  • AppsFlyer 依赖已集成，且初始化同时传入 devKey 和 appleAppID。
  • 初始化 completion 已检查每个渠道的 state。
  • Facebook/TikTok 配置与实际选择的 subspec 一致。
  • Firebase 仅在需要时添加 Firebase subspec，并将 GoogleService-Info.plist 加入宿主 Target。
  • Expo 项目使用 development build 或 EAS Build，没有使用 Expo Go 加载 SATagSDK。
  • 统一事件和单渠道事件使用非空事件名。
  • 未初始化或未集成渠道打点不会导致崩溃。
  • DebugView 可以从真实页面打开。
  • 没有输出完整敏感配置。
  • XCFramework 方式没有重复添加第三方 SDK。
